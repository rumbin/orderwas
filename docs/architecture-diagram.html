Orderwas — Service Architecture

Open-source ordering & receipt-printing for club festivals

Layering Rules (binding)

  • • Routes are thin: Zod → service → HTTP response
  • • Services own all business logic
  • • No Prisma in routes — services get the client
  • • Side effects fan out from services
  • • PIN is write-only: never returned to client
  • • Money = integer cents everywhere

Frontend (PWA)

  • • React 18 + Vite 5 + Tailwind CSS
  • • Zustand stores: session, cart
  • • react-i18next (DE primary, EN, FR)
  • • Socket.io client for live updates
  • • Pages: Order, Admin, Kitchen, Station
  • • Offline PWA via vite-plugin-pwa

Backend Services

  • • orderService — creation, totals, tear-off
  • • eventService — lifecycle, test→live wipe
  • • printerService — ESC/POS formatting + TCP
  • • stockService — tracked & composite
  • • voucherService — Bonkasse vouchers
  • • auditService — export & reporting
